## Local release checks

Install dependencies and the browser used by the audits:

```sh
bundle install
npm ci
npx playwright install chromium
```

Build the Jekyll site, then place the tested Słowo Analyzer build in `_site/slowo-analyzer/` before running the validators:

```sh
bundle exec jekyll build --baseurl ""
ruby scripts/prepare_slowo_analyzer.rb ../slowo-analyzer/dist _site/slowo-analyzer
ruby scripts/check_site.rb _site
```

Serve the build for Axe in one terminal:

```sh
python3 -m http.server 4001 --directory _site
```

Run the audits from another terminal:

```sh
npm run audit:axe
npm run audit:lighthouse
```

Axe is a CI gate and fails on `serious` or `critical` violations. Lighthouse is deliberately a release check because performance scores vary with the runner. It performs three mobile runs for Home, BHTOM, Experience and Personal and enforces:

- Performance ≥ 90
- Accessibility, Best Practices and SEO ≥ 95
- CLS < 0.1
- LCP ≤ 2.5 s

Lighthouse reports are written to the ignored `tmp/lighthouse/` directory.

## CI and branch policy

- Pushes to `codex/**`, pull requests and `master` always run the Jekyll build, Słowo Analyzer tests and build, HTML/internal-link/analytics validation and Axe.
- Only a successful `master` run can enter the deployment job.
- Never force-push the release branch.
- Before merging, update the release branch from the current `master` if production has changed and rerun every check.

## Domain verification and migration

1. In the GitHub account Pages settings, add `krzkot.com` as a verified domain.
2. Add the TXT value generated by GitHub in OVH at `_github-pages-challenge-kkotysz.krzkot.com`, wait for propagation, click **Verify**, and keep the TXT record permanently.
3. Optionally lower the TTL for apex and `www` to 300 seconds at least one hour before the switch.
4. Once the branch and audits are approved, set the repository Pages custom domain to `krzkot.com`.
5. Immediately replace the old apex A record `87.98.239.5` with:
   - `185.199.108.153`
   - `185.199.109.153`
   - `185.199.110.153`
   - `185.199.111.153`
6. Add the apex AAAA records:
   - `2606:50c0:8000::153`
   - `2606:50c0:8001::153`
   - `2606:50c0:8002::153`
   - `2606:50c0:8003::153`
7. Keep `www` as a CNAME to `plokoon12.github.io`; do not add wildcard records.
8. Keep the old `master` deployed until `https://krzkot.com` returns 200 with a valid certificate and `https://www.krzkot.com` redirects to the apex.
9. Enable **Enforce HTTPS** when GitHub makes the option available.
10. Only then merge the reviewed branch into the current `master`. The `master` push deploys the portfolio.

The repository `CNAME` records the intended apex domain, but for a GitHub Actions Pages deployment the Pages custom-domain setting remains authoritative.
